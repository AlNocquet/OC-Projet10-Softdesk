# SoftDesk Support (Bug Tracker API)

## Overview

SoftDesk Support is a secure RESTful bug-tracking backend built with **Django** and **Django REST Framework**.

Authenticated users can manage:
- projects
- contributors
- issues
- comments

Authentication relies on **JWT**, permissions are enforced at both authentication and object levels, and API lists are **paginated** by default. The application also includes a GDPR-oriented profile endpoint for user data access, update, and deletion.

## Features

- JWT authentication (`access` / `refresh`)
- Projects restricted to their contributors
- Author-only update/delete for `Project`, `Issue`, and `Comment`
- Contributors management per project
- Issues with:
  - priority (`LOW`, `MEDIUM`, `HIGH`)
  - tag (`BUG`, `FEATURE`, `TASK`)
  - status (`TO_DO`, `IN_PROGRESS`, `FINISHED`)
  - optional assignee restricted to project contributors
- Comments linked to issues
- Comment UUID autogenerated at model level
- Global pagination
- GDPR profile endpoint:
  - access personal data
  - update consent fields
  - delete account

## Tech Stack

## Authentication (JWT)

POST http://127.0.0.1:8000/api/auth/token/

{
  "username": "<user>",
  "password": "<password>"
}

POST http://127.0.0.1:8000/api/auth/token/refresh/

Authorization: Bearer <ACCESS_TOKEN>

## API Map

/api/auth/token/                             POST
/api/auth/token/refresh/                     POST

/api/projects/                               GET, POST
/api/projects/{id}/                          GET, PATCH, DELETE

/api/projects/{id}/contributors/             GET, POST
/api/projects/{project_id}/contributors/{contributor_id}/        DELETE

/api/projects/{project_id}/issues/           GET, POST
/api/projects/{project_id}/issues/{id}/      GET, PATCH, DELETE

/api/projects/{project_id}/issues/{issue_id}/comments/        GET, POST
/api/projects/{project_id}/issues/{issue_id}/comments/{id}/   GET, PATCH, DELETE

/api/profile/                                GET, PATCH, DELETE

## Permissions

- All API endpoints require authentication by default (except /health)
- A project is visible only to its contributors
- A contributor can read project-related resources
- Only the author of a Project, Issue, or Comment can update or delete it
- Only the project author can add or remove contributors

## GDPR

GET    /api/profile/
PATCH  /api/profile/
DELETE /api/profile/

Handled data:
- age
- can_be_contacted
- can_data_be_shared

Rules:
- age must be >= 15
- authenticated users can access and update their profile
- authenticated users can delete their account

## Pagination

The API uses Django REST Framework global pagination:

- Pagination type: PageNumberPagination
- Page size: 10 items per page

Example:
GET /api/projects/?page=2

## Security (AAA)

The API follows the AAA model:

- **Authentication**:
  - JWT-based authentication using access and refresh tokens

- **Authorization**:
  - Access restricted to authenticated users
  - Project data accessible only to contributors
  - Write operations restricted to resource authors

- **Accounting**:
  - Basic request handling is provided by Django
  - Advanced logging of user actions could be implemented for production environments

## Project Structure

```
config/         # project settings and root urls

```

## Testing

The API has been tested using:

- Postman (main testing tool with JWT authentication and environments)
- Django test files (`tests.py`) for basic automated validation

Postman was used to simulate real client interactions (authentication, permissions, CRUD operations), while Django tests ensure minimal automated verification of core behaviors.
